# .instructions.md — Project Rules (The Manager)

> Read this file at the start of every session. Follow these rules. Keep this file under 100 lines.

## Session Start

1. YOU MUST read `.instructions.md`, `CONTEXT.md`, `DEVLOG.md`, and `PRD.md` at the start of every session, in that order.
2. YOU MUST work ONLY on the task listed in `CONTEXT.md`. No side quests, no refactors outside scope.

## Core Rules

3. NEVER commit, print, or expose `.env` contents. Secrets (API keys, model URLs) stay server-side. `/api/config` MUST NOT return the API key.
4. NEVER put real endpoints or keys in `.env.example` — placeholders only (`api_location_here`, `your_key_here`). The example is a template and gets committed.
5. NEVER commit `settings.json` or `prefs.json` — they are deprecated and gitignored; settings live in `.env`.
6. NEVER delete or rewrite DEVLOG.md history. Entries are append-only. Add a new `## YYYY-MM-DD` entry per session, even for small changes.
7. NEVER leave the app broken. If you change code, run `npm test` before finishing. All three suites (engine-sim, render-exhaustive, smoke) must pass.
8. NEVER echo secrets or full API keys in logs, tests, or client code.

## Work Flow

8. DO keep changes surgical: edit the smallest file(s) that solve the task in `CONTEXT.md`.
9. DO keep the engine server-authoritative. Client flips are cosmetic for the asker; the server (`lib/engine.js`) owns state.
10. DO keep fallbacks: any AI/LLM feature MUST fall back to the local judge (`lib/judge.js`) when the API is unreachable. The game must always work without AI.
11. DO keep env-loading safe: `lib/llm.js` seeds lazily from `process.env` on first use — never require AI config before `.env` is loaded in `server.js`.
12. DO mark bot answers with a type field on all socket broadcast events (e.g. `answer`), and end matches with winner + last guess (`lastGuess`) so the UI can report them.
13. DO use seeded generation (`mulberry32` + seed) so every client renders the same board from server-sent features.
14. DO keep PI ("politically incorrect") mode bounded: playful/edgy phrasing allowed, NEVER slurs, hate speech, or harassment. Stay a game.
15. DO use snake_case in `lib/` engine code, and keep `public/app.js` free of duplicate log entries (single append per event).

## Testing & Validation

16. YOU MUST run `npm test` after any change to `lib/`, `server.js`, or `public/app.js` logic, and fix failures before finishing.
17. For AI/bot changes, also run the engine simulation (`node test/engine-sim.js`) — verify the bot strategy does not repeat uninformative questions (no local minima).
18. For visual changes, render sample boards with `node test/render-faces.js` to `.render-out/` for QA.

## Session Close (the Write Phase)

19. YOU MUST update `CONTEXT.md` with: what was done, current state, and the exact NEXT step.
20. YOU MUST append a `## YYYY-MM-DD` entry to `DEVLOG.md`: what you did, why, and any errors found + how they were fixed.
21. YOU MUST note in DEVLOG.md/CONTEXT.md if `PRD.md` success metrics changed.
